## The gaps, by what they cost

### Wrong writes, or writes that should be refused
1. **Tasks turned off** (ref 2014): linking a task, or adding or listing notes on one, still runs — the
   guard in `policy._check_rules` covers task ops only. Refuse when any resolved record is a task.
2. **"add a note: …" with no record named** (ref 1898): looked up as a contact (`_UNSAID_KIND`) and,
   exempt from the stale check, written without asking. Point an unnamed note at the most recent record.
3. **A work-item note with no text** (refs 995, 1018): `add_work_item_note.body` is required, so the
   model sends `" "` (a blank note) or fails; the note-text question covers `add_note` only.
4. **"the last task" / "my latest task"** (ref 1996): the bare-name retry ("last") matches a title
   like "Last mow of the season" before the recency lookup (#841). Try the task finder's recency and
   date words first.
5. **An estimate with an unknown stored status** (side finding, #848): refused with no words, which
   planner only says as "I can't do that yet". It should stay editable.

### Answered by today's pipeline before; planner only now says "I can't" or loses the turn
6. **"does that include tax?" after a list's total** (ref 426, #905).
7. **"how about for Ana Reyes?" after a notes list** (ref 1422): `list_notes` isn't a replayable read.
8. **The field-then-value flow** (refs 1283, 1366, 1620; tasks 1926, 1928, 1930, 1961, 2004):
   "update Bob's record" → "phone" never asks for the value — the plan can't say "this field, value
   unknown". Add `ask_for` on the updates and today's per-field questions.
9. **A work item picked from several** (refs 990, 1016): the question has no options, so "2" can't pick.
10. **"add a work item" with no name** (ref 991): no name question; the model invents one.
11. **An estimate code answering the planner's "which estimate?"** (ref 993): read as a new request.
12. **A description that reads like a command** (ref 1017): a planner `clarify` waits for an answer,
    not free text.
13. **"no" / "skip" to the template size question** (ref 1744): cancels instead of creating at the
    template's baseline.
14. **The offer after a create** ("Would you like to add an email?", side finding, #913): shown but not
    kept, so "yes" gets "I'm not waiting on an answer".
15. **"make it 800"** (ref 543): the size's unit must be guessed; a wrong one prices the item again.
16. **An email outside the team as a task's assignee** (refs 1955, 1957): the teammate check loops.
17. **A misspelled property** (ref 2392): no fuzzy tier — "I couldn't find …", never "did you mean?".
18. **An unrecognised reply to a numbered menu** (ref 2395): the menu isn't shown again.
19. **"the last estimate" with none** (ref 856): asks which, instead of "You don't have any estimates yet."

### Wording only
20. A typed database id is asked about without today's reason (ref 855); "what sizes does it come in?"
    off a material (ref 1502); "More than one contact matches that" vs "I found 2 contacts called Ana"
    (ref 2461).
21. "this month vs last month" → "and last year?" gives the year's figure, not a comparison (ref 1204) —
    deliberate, pinned by a test; the reference row should be updated.

### Fixed during the audit
- **A handler's own yes/no question asked on a planner turn** (refs 988, 660; today's removal,
  "Just to check" and near-miss division questions): with `MAPLE_PLANNER_ONLY` on, its "yes" got "I've
  lost track of that question", so a work item's removal could never be confirmed. Such a question is
  now marked when asked (`kept_questions.ASKED_ON_PLANNER_KEY`) and answered by its handler; only a
  question left from before the switch is dropped.
